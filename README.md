# A Simple Method for Processing Unorganized Items

A simple, human-readable method for working through a collection one item or
group at a time. Choose the scope, decide what to do, then act and check the
results. The same guidance applies to people and agents.

## Versioning

The shared method and each specialization have independent versions. Existing
tags such as `v1.2.0` identify shared-method releases. Specialization tags use a
stable method name, such as `mail/v1.0.0`. There is no additional global version.

Each specialization declares its own version and the exact released shared
version it follows. A new shared release calls for compatibility review before
deliberate adoption; it does not change existing specialization releases.

For method documents, use a patch version for wording corrections that preserve
guidance, a minor version for compatible additions or clarifications, and a major
version for incompatible guidance requiring existing workflows or
implementations to change. Adoption of another governing version requires a new
specialization version; choose the increment by its effect, not by matching the
shared version number. Published tags stay fixed. Repository maintenance alone
does not require a method release.
